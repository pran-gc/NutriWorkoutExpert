Phase 5 — Cross-cutting QA rules

  • States: every screen ships with empty, loading (skeleton, no spinner-only), and error states. Errors use the amber banner + retry; forms show inline messages. Blank screens are defects.
  • Dark mode: token flip only — no per-screen dark styling. If a screen needs a special dark rule, the token model is wrong; fix the token.
  • Motion tokens (NWE-606): micro 150 ms ease-out (chips, checks) · standard 250 ms ease-out (sheets, cards) · celebrate 450 ms spring (rings close, badge unlock). Haptics on wins only. prefers-reduced-motion/`isReduceMotionEnabled` → static equivalents. Animations never block input.
  • Accessibility: color never encodes alone (macro rings carry text labels); touch targets ≥ 44 pt; text contrast ≥ 4.5:1 on both themes (accent-on-white passes at 15 px semibold+); dynamic type must not clip cards — cards hug content.
  • Numbers: tabular figures wherever digits align (totals, set rows, times). Metric only. Thin-space thousands separator ("2 150").
  • Copy: encouraging, never guilt ("Fresh start today", not "You broke your streak"). Buttons say what they do ("Log meal", not "OK"). AI content is attributed to its coach and deletable.
  • Privacy surfaces: "never stored" messaging appears at every photo touchpoint (viewer, compare screen, consent sheet, progress grid).
